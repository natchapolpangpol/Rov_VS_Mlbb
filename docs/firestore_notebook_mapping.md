## สิ่งที่ notebook ไม่ได้บันทึกไว้จริง

1. **เวลาเก็บยอดวิว YouTube:** `published_at` คือเวลาเผยแพร่คลิป; CSV_COLUMNS/base_row ไม่มี `collected_at` และ cell metadata ที่บันทึกไว้ไม่มีเวลา execution ตัวเลข AFTER_END เป็นขอบเขตคลิป ไม่ใช่วันเก็บยอดวิว
2. **เขตเวลาของค่ารีวิวแบบไม่มี offset:** โค้ดใช้ `pd.to_datetime` และ `isoformat()` แต่ไม่ได้กำหนด timezone ให้ `at`; หลักฐานว่าเป็น Colab ทำให้ UTC เป็นสมมติฐานที่พิจารณาได้ แต่ไม่ใช่ field ที่บันทึกไว้โดยตรง
3. **สเกล query ของแต่ละแถว Trends:** มีโค้ดแบ่งช่วง แต่ไฟล์หลัง concat ไม่เก็บ query/window ID ทำให้รอยต่อที่วันซ้ำมี provenance ไม่ครบ

จะเก็บประเด็นเหล่านี้เป็น metadata/ข้อจำกัดและทำงานส่วนที่ข้อมูลรองรับต่อ ไม่ใส่วัน export ปัจจุบันแทนวันเก็บเดิม และไม่ใช้ Firestore createTime เป็นวันเก็บต้นทางโดยไม่มีหลักฐาน

## ผลต่อแผนทำงาน

- ใช้ snapshot ที่ export ครบแล้วเป็น raw ของข้อมูลเก่า รักษาชื่อเอกสารและ create/update time ของ Firestore ไว้สำหรับตรวจย้อนกลับ
- ทำ adapter ให้แยก original collection time ที่ไม่ทราบออกจาก export time ที่ทราบ พร้อมระบุสมมติฐานเวลาอย่างเปิดเผย
- ใช้ notebook เดิมเป็นแหล่งขอบเขตและวิธีเลือกข้อมูล แทนการถามข้อมูลที่หาได้จากไฟล์
- ตรวจและแก้ Trends ก่อนนำไปสรุปข้ามเวลา; รักษาต้นฉบับไว้เพื่อแสดงว่าปัญหาเกิดจากขั้นใด
- ยังคงใช้ SQLite เป็นฐานข้อมูลพอร์ตหลัก Firestore เป็นแหล่งนำเข้าข้อมูลของงานกลุ่ม ไม่ได้เปลี่ยนกลับไปพึ่งฐานข้อมูลของเพื่อนสำหรับทุกครั้งที่รัน
